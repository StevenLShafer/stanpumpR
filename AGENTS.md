# AGENTS.md — AI Agent Orientation

**stanpumpR** is an R package + Shiny app for PK/PD simulation. It calculates and plots predicted plasma ($C_p$) and effect-site ($C_e$) concentrations for IV and extravascular anesthetics using **analytical closed-form 3-compartment solutions** (no ODE solver). Stack/version details: `DESCRIPTION`. Entry point: `app.R` → `stanpumpR::run_app()`.

---

## Quick Commands

```r
devtools::load_all(".")   # Load package functions locally
run_app()                 # Launch Shiny app locally (add ?debug=1 to URL for profiler/log)
devtools::test()          # Run testthat unit test suite
devtools::document()      # Update NAMESPACE and man/ documentation
renv::restore()           # Restore pinned R package dependencies from renv.lock
```

First-time local setup: copy `config.yml.sample` → `config.yml`

## Architecture: Reactive Request-to-Render Pipeline (`R/app_server.R`)

*Full details available in `docs/architecture.md`*

1. **Inputs**: Patient covariates, dose grid (`rhandsontable`), clinical events, plot settings.
2. **Validate**: `doseTableClean()`, `eventTableClean()`, `testCovariates()`.
3. **Resolve PK**: `recalculatePK()` calls `getDrugPK()`, which converts covariates → micro rate constants → eigenvalues (`cube()`) → $k_{e0}$ (solved by `tPeakError()` + `CE()`) → exponential coefficients.
4. **Simulate**: `processdoseTable()` calls `simCpCe()`, which first expands any `qd`/`bid`/`tid`/`qid` dose into its repeats to the end of the plot (`scheduled.R`; returned as `$scheduled` for export) and any `Plasma target` / `Effect site target` rows into a TCI infusion schedule (`tci.R`, Shafer & Gregg 1992; returned as `$tci` for the rate panel and export), then dispatches to:
   - `advanceClosedForm0.R` (IV, standard PK)
   - `advanceClosedForm1.R` (time-varying PK with events)
   - `advanceClosedFormPO_IM_IN.R` (extravascular 1st-order absorption: PO, SL (sublingual), IM, IN and RA, regional anesthesia, a local anesthetic injected into tissue — `ka_RA`/`bioavailability_RA`/`tlag_RA`, units `raUnits`; tests `test-route-ra.R`)
   - `advanceMichaelisMenten.R` (numerical 1-compartment with saturable, Michaelis-Menten elimination — the one non-superposable engine, for phenytoin; a drug declares it with a `michaelisMenten` block (`vmax`, `km`, per-product `saltFactor`, optional `kConversion`/`ka_IM` for a prodrug route like fosphenytoin's `mg PE`). Integrates the whole dose table at once, so `simCpCe()` dispatches here before it splits oral formulations; tests `test-michaelis-menten.R`)
5. **Plot & Render**: `simulationPlot.R` generates `ggplot2` output.

`processdoseTable()` re-simulates only the drugs whose inputs changed: `drugs()` passes it the previous result as `cache`, and a drug whose `simulationKey()` (PK, dose rows, PK events, plot length, recovery switch) is unchanged reuses its own stored simulation. `foldMetabolites()` always re-runs on top.

**Dose table lifecycle**: edits land in a draft held by an `{undomanager}` (`doseTableHistory()`, with `doseTableDraft()` a thin reactive over its `$value`) that owns the undo/redo history; `Apply` commits it to the canonical `doseTable()`; `doseTableClean()` (cleaned via `cleanDoseTable()` in `input-tables.R`) is what the rest of the pipeline actually reads. Clicking the plot to add/edit a dose bypasses the draft and applies immediately, and any direct write to `doseTable()` resets the draft and clears the history.

**Startup** (`R/startup-drugs.R`): a session starts with an empty dose table (`doseTableBlank`) and, unless the URL restores a bookmark with drugs in its dose table, `app_server()` shows a modal of checkboxes grouped by the CSV's `Category` column (`DRUG_CATEGORIES` order; `STARTUP_DRUGS_DEFAULT` ticked). **Start** writes `startupDoseTable()` to `doseTable()` through `setDoseTable()`, in the table's current time format (its times are all `"0"`); with the defaults that is exactly `doseTableInit`, the table the app opened with before the menu. Shiny "restores" from any query string, so `?debug=1` alone is not a bookmark: `isBookmarkRestore()` requires a `DT` value, and `onRestored()` returns early without one. The weekly welcome text (`show_intro_modal` from `app.js`) is rendered into the open menu rather than replacing it. Tests: `test-startup-drugs.R`.

**Illicit drugs** (`R/illicit-drugs.R`): drugs in the `Illicit drugs` category (`ILLICIT_DRUG_CATEGORY`) are opt-in, evidence-labelled research models of drugs of abuse (diamorphine is the first, `R/drugs_diamorphine.R`). A persistent checkbox, **Show illicit drugs** (`input$showIllicitDrugs`), off by default, gates them: when off they are not offered in the dose-table autocomplete or the Add a dose dialog (`drugChoices()` → `visibleDrugNames()`), and the startup menu never lists them (`startupDrugChoices()`); when on they appear, with their names drawn in red in the dose table (`createHOT()` renderer, reading the `drug_defaults` global by `Category`). Restoring a bookmark whose dose table holds an illicit drug turns the opt-in on so the drug is not hidden from its own table. Tests: `test-illicit-drugs.R`.

**Scheduled doses** (`R/scheduled.R`): a bolus, PO, SL, IM or IN unit followed by `qd`, `bid`, `tid` or `qid` (`"mg PO bid"`; the full list is `scheduledUnits`, intervals in minutes are `SCHEDULE_INTERVALS` in `R/constants.R`) gives the dose at the time entered and repeats it every interval until the end of the plot. Rules, per route (IV, PO, SL, IM, IN) within a drug: a scheduled dose of 0 at any frequency stops the sequence (an ordinary dose of 0 does not); a later non-zero scheduled row replaces the running sequence from its own time; two scheduled rows at the same time keep the last one entered. As with TCI, the repeats never enter the editable dose table: `expandScheduledDoses()` runs first in `simCpCe()`, turning each scheduled row into its base unit plus the repeats, so the engines and `doseRoute()` only ever see ordinary units; the repeats are returned as `$scheduled` (Drug, Time, Dose, Units), carried through the simulation cache, and merged with the TCI rows into the exported dose table by `exportDoseTable()`. Which drugs offer the frequencies is set by their `Units` in `drugDefaults_global.csv` (opioid analgesics, antibiotics, steroids; not the anaesthetics, TCI-only drugs, or mannitol, which is infusion-only). Tests: `test-scheduled.R`.

**The TCI API** (`R/tci-api.R`, `R/tci-api-server.R`; normative reference `docs/tci-api.md`, help page `inst/help/tci-api.md`): a stateless HTTP API under `/tci/v1` that hands a TCI pump controller its next rate for one drug in one patient, re-deriving the model state from the controller's delivery history on every request (the STANPUMP principle). `tciNextRate(request)` (exported, pure R, no Shiny, no plumber) takes the body as `jsonlite::fromJSON(txt, simplifyVector = FALSE)` gives it, rebuilds the seven-amplitude state from the history (rate changes, delivered segments, hand boluses, infusate changes), projects it through the declared `timing.latency`, calls the app's `tciRate()`, applies `pump.maxRate` / `minRate` / `rateResolution` (always rounding down) and returns the response list (`rate`, `segment`, `fallback`, `timing`, `state`, `prediction`, `model`, `warnings`); validation raises the classed condition `tci_api_error` (`status`, `code`, `message`, `pointer`). Field names, unit tokens (the library's spellings: `mL/hr`, `mcg`; one closed list, no aliases), error codes, HTTP statuses and the `TCI_API_*` bounds in `R/constants.R` are fixed by `docs/tci-api.md`: within `/tci/v1` only add, never change a meaning. `tciApiRouter()` / `run_tci_api()` wrap it in plumber (`inst/api/entrypoint.R` for `rsconnect::deployAPI()`, `inst/api/openapi.json` hand-written); shinyapps.io does not host it. Tests: `test-tci-api.R` (the closed loop reproduces `tciSchedule()` rate for rate at zero latency; every error and warning code) and `test-tci-api-http.R` (in-process `pr$call()` on `rookRequest()` from `helpers.R`; skipped without plumber). [FauxTCI](https://github.com/StevenLShafer/FauxTCI) (served at https://stevenlshafer.github.io/FauxTCI/) is a browser pump built to this contract: a JavaScript port of the controller validated against fixtures that its `test/fixtures/generate.R` produces from this package, so a change to `tciNextRate()`'s numbers or to `docs/tci-api.md` is a change FauxTCI must follow.

**Time units** (`R/utils-time.R`; `docs/architecture.md#time-units`): minutes / hours / days / weeks are entry and display only — the engine, events, scenarios, `input$maximum` values, `simulationKey()` and exported Time columns stay in minutes. The dose table holds its Time strings as typed, in the format (`c(unit, mode)`) recorded by `doseTableFormat()`; `doseTableClean()` reads them with that record, never the selectors. Write a new table with its format through `setDoseTable()` (or `timeApi` from outside `app_server()`); a selector change is converted by one observer (`rebaseDoseTimes()`), and `plotInfo()` waits while record and selectors disagree. Max time choices are per unit (`MAX_TIMES`); TCI rows and inhaled agents only on plots of a week or less. Tests: `test-utils-time.R`, `test-time-units-server.R`.

**Testing/scripting entry point**: `simulateDrugsWithCovariates()` is the exported, Shiny-free API (loops `getDrugPK()` → `simCpCe()` per drug) — used by tests and vignettes to drive the PK/PD core without the app.

**Minto / Schnider** (`R/alternativeModels.R`): a Graph Options checkbox (`input$mintoSchnider`, enabled while propofol or remifentanil is dosed) runs Schnider's 1998 propofol and Minto's 1997 remifentanil models, the models in most TCI pumps, beside the library's Eleveld models. Each is a *companion entry* of the drug list, named `propofol (Schnider)` / `remifentanil (Minto)` with `$companionOf` and `$modelLabel`: `recalculatePK(alternativeModels = TRUE)` builds it through `getDrugPK(model = ...)`, `processdoseTable()` simulates it on the parent's doses with recovery off (the time until threshold stays on Eleveld), and `simulationPlot()` draws it as a second line in the parent's panel (colour from `alternativeModelColor()`, own legend entry) and its TCI pump as a second line on the parent's rate panel. Companions are excluded from the MEAC sum, the interaction panel and the opioid-MAC interaction; `alternativeModelParent()` maps a companion's series name back to the parent for the hover and the click. Minto supplies `ke0` as a function of age with no `tPeak`, which `getDrugPK()` now accepts, solving the time to peak effect from `ke0`. A model whose covariate terms give a non-positive parameter for the patient is skipped and `alternativeModelProblems()` says why (shown as a notification). Help page `inst/help/models/minto-schnider.md` (generated block `minto-schnider-table`); scenarios `eleveld-vs-minto-schnider`, `tci-eleveld-vs-minto-schnider` (scenario option `mintoSchnider`). Tests: `test-minto-schnider.R`.

**Simulation API** (`R/api.R`, `inst/plumber/plumber.R`; spec `inst/apidocs/api.md`, published at https://stanpumpr.io/api; help page `inst/help/simulation-api.md`): `apiSimulate(request)` validates a request (patient, dose table, duration, `timeUnit`, events, output grid), runs `simulateDrugsWithCovariates()`, and returns `meta`/`patient`/`drugs`/`doses`/`timeseries`/`warnings`, always in minutes, kg, cm and years; `apiFormatResult()` serialises it as JSON, CSV, xlsx or XML; `run_api()` serves `POST /simulate`, `GET /drugs`, `GET /health` with plumber (a Suggests). The requested output times are simulated exactly, not interpolated: `withOutputTimes()` adds them as extra points to every `simulationTimeGrid()` line, and nothing is added outside it. Request errors are `stanpumpr_api_error` conditions (HTTP 400). Inhaled agents are refused. Illicit drugs need `options.allowIllicitDrugs`. The spec is the integrator-facing documentation: `apiDocsHtml()` (`R/api-docs.R`) renders it into a self-contained page that `run_app()` serves as the resource path `api` (so `<app>/api`) and `run_api()` serves at `/`; keep it in step with the code. Tests: `test-api.R`, `test-api-docs.R`.

## Key Rules

- **Adding a drug** requires all four (full procedure: `docs/adding-a-drug.md`):
  1. `R/drugs_<name>.R` (covariate model function)
  2. `inst/extdata/drugDefaults_global.csv` (row with colors, units, MEAC, and the `Category` that lists it in the startup menu)
  3. `tests/testthat/test-drugs-<name>.R` (unit test — pin values with `expect_equal_rounded()` from `tests/testthat/helpers.R`)
  4. `inst/help/drugs/<name>.md` (the narrative for the drug's generated help page; `test-help-drugs.R` fails without it)
- **Body size scaling is mandatory** (`docs/weight-adjustment.md`): a drug function is `<name>(weight, height, age, sex, adjustToFFM = TRUE)` and either carries its own size covariate (Eleveld-style) or scales its 70 kg reference parameters with `pkSizeFactors()` — volumes by `$volume`, clearances by `$clearance` — passing the `legacy*` factors that reproduce the published scaling when the switch is off. Tests pin both switch positions.
- **Renal covariates**: a model with a creatinine-clearance or eGFR term adds `creatinine = NULL` to its signature (getDrugPK passes the Patient Profile's serum creatinine only to models that name it) and computes renal function with `R/renalFunction.R`, passing `adultEquivalentCreatinine(creatinine, age, sex)` to an equation fitted in adults (Cockcroft-Gault, CKD-EPI), which puts a child's creatinine on the adult scale, or `patientCreatinine(creatinine, age, sex)` only where the source applied its equation to children's own creatinine (pregabalin). A blank field is NULL, which means an assumed normal creatinine for the patient's age and sex (`assumedCreatinine()`: 1.0 / 0.8 mg/dL from 18, the median for age below); the drug header and `reference` string must say so.
- **Two oral absorption paths or a sum of systems**: a second lagged oral depot is `ka_PO2`/`fraction_PO2`/`tlag_PO2` (diclofenac, meloxicam; with a metabolite, aspirin, whose salicylate the metabolite engine forms from both depots); a drug plotted as the sum of independent linear systems returns `parallelSystems` + `doseFraction`, which `simCpCe()` runs separately and adds (ketorolac S + R); a system can be limited to some `routes`, which is how meloxicam's oral fit and its separate IV fit (ANJESO) share one drug. Both in `docs/adding-a-drug.md`.
- **Intravenous calcium** (`R/drugs_calcium.R`; Ansari 2025, parturients at cesarean delivery, offered to every patient as the only adult PK of intravenous calcium): one drug, `calcium`, for both salts, plotted as the *change* in ionized calcium, mmol/L, above an unmodelled baseline, so a patient given both gets one summed curve. Every unit names the salt (`g chloride`, `mg/min gluconate`; `calciumUnits` from `CALCIUM_SALTS` in `R/constants.R`, no bare `g`), read by `doseProduct()` in `R/routes.R`. The CSV `Concentration.Units` `mmol` means amounts in millimoles: the model returns `molar = list(molecularWeight = ...)`, grams of the product as dosed per mole of what is plotted, as one number or a vector named by product (`validateMolar()` in `getDrugPK.R`); `simCpCe()` converts each dose by the weight its unit names (`molarWeightOfDoses()`, which refuses a unit naming no product), and calcium gluconate's is calcium chloride's 147.01 × the fitted dose ratio 3.11. Plasma only, no band. Scenario `calcium-salt-substitution`. Tests: `test-drugs-calcium.R`.
- **Non-linear or non-mammillary sources** (saturable binding, reversible metabolite pairs, a racemate of two enantiomers) must be reduced to the linear engine with the reduction documented in the drug header: see `R/drugs_cefazolin.R`, `R/drugs_hydrocortisone.R`, `R/drugs_prednisolone.R`, `R/drugs_citalopram.R`. The exception is dose-dependent oral or sublingual bioavailability, which a drug declares as an `oralSaturation` or `sublingualSaturation` block and `simCpCe()` applies to each such dose before the engine (`oralSaturationFraction()` in `R/routes.R`; forms `saturable` (gabapentin, buprenorphine SL), `rising` (sertraline) and `power` (paroxetine)). A pulsed extended-release product (Adderall XR) declares an `oralPulses` block: each `mg PO XR` dose becomes fixed fractions at fixed delays, each absorbed as the default oral form (`expandOralPulses()` in `R/oral-pulses.R`, run after the scheduled expansion; example `R/drugs_mixedAmphetamineSalts.R`; tests `test-oral-pulses.R`).
- **Pharmacogenetic covariates**: `cyp2d6`, `cyp2c19`, `cyp2c9` and `cyp2b6` reach only models that name them in their signature (`CYP2D6_VALUES`, `CYP2C19_VALUES`, `CYP2C9_VALUES`, `CYP2B6_VALUES` in `R/constants.R`; Patient Profile fields **CYP 2D6**, **CYP 2C19**, **CYP 2C9**, **CYP 2B6**). `cyp2c9` is read by phenytoin, on its `Vmax`, and by meloxicam. `cyp2b6` is read only by methadone, where it scales each enantiomer's non-renal clearance (Kharasch 2015; the rapid and ultrarapid phenotypes take the normal metaboliser's values, and `R/drugs_methadone.R` says why). A model that declares `cyp2c19` or `cyp2b6` gets a generated clearance-by-phenotype table on its help page (`R/help-drugs.R`). Scenarios: `codeine-cyp2d6`, `methadone-cyp2b6`, `phenytoin-saturable-metabolism`.
- **Antiseizure drugs** (`inst/help/models` has no page; category `Antiseizure` in `DRUG_CATEGORIES`): FDA-approved, US-available antiseizure ingredients. Only those with a complete, validated published population model are in the library and selectable (carbamazepine, eslicarbazepine, ethosuximide, lacosamide, lamotrigine, levetiracetam, pentobarbital, phenobarbital, phenytoin — with fosphenytoin as its `mg PE` route — tiagabine, topiramate, valproate, zonisamide; plus the pre-existing gabapentin, pregabalin and the benzodiazepines). Every FDA-approved US-available ingredient/prodrug (37 entries) is catalogued in the machine-readable registry `inst/extdata/antiseizureRegistry.csv` with its US status, evidence tier, dose basis, analyte and source; the per-parameter audit (value, units, provenance, population, source URL) is `inst/extdata/antiseizureParameters.csv`; both are rebuilt by `data-raw/antiseizureRegistry.R` and checked by `test-antiseizure-registry.R`. Drugs whose source constants are unestimated stay registry-only (an implementation queue), never a selectable curve; Acthar Gel is `PK_UNAVAILABLE`. "ER"/"DR" oral formulation units and the `mg PE` prodrug-equivalent units are in `R/constants.R`. No numeric seizure PD is enabled: the drugs are plasma-only.
- **Antidepressants** (`inst/help/models/antidepressants.md`): source-specific population PK presets only. Fluoxetine (Han 2025) is in, but fitted to steady-state troughs only, so its time course is not physiological and its pages say so. Venlafaxine (Wang 2022) is in, with K23 = CL/V read from the paper's Figure 1. Feng 2006's nonlinear paroxetine model is deliberately absent: the full paper prints no input convention that makes its Vmax compatible with its own predictions (inst/help/models/antidepressants.md); transporter occupancy and symptom response are not plotted.
- **Antipsychotics** (`docs/antipsychotics.md`): an apparent (`/F`) parameter set and an absolute IV one are separate drugs (`haloperidol` / `haloperidolIV`, `droperidol` / `droperidolIM`). D2 occupancy lives in `antipsychoticProfiles()` (`R/antipsychotics.R`), not in the MEAC or the band, which are zero.
- **Rate constants must never tie**: every closed-form coefficient divides by a difference of two rate constants (`ke0 - lambda_i`, `ka - lambda_i`, `ka - ke0`, a metabolite's `mu - lambda`), so an exact tie is a division by zero. `getDrugPK()` runs ke0 and every `ka_*` through `separateEigenvalues()` (`R/metaboliteCoefficients.R`, a relative nudge of 1e-8) once, and returns the nudged values, so every engine sees rates that are already separate; the helpers that take a rate from elsewhere (`oralCoefficients()`, `effectSitePeakTime()`, `tPeakError()`, `effectSiteCoefficients()`, the depot and ke0 guards in `advanceClosedForm1()`) apply it again. `calculateCe()` instead evaluates the limiting form when a step's log plasma slope equals `-ke0`. A new division by a rate difference goes through the same helper. Tests: `test-separated-rates.R`, `test-calculateCe.R`.
- **Debug logging**: `outputComments()`, active when `?debug=1` is in the URL.
- **Deploy**: GitHub Actions — PRs auto-deploy to a test environment; a push to `master` deploys to production (shinyapps.io) only after `R-CMD-check` has passed on it (`workflow_run` in `shiny-deploy-production.yaml`), and the deploy installs that exact commit (`@sha`), fails if the installed `RemoteSha` differs, and writes the SHA into the deployed `config.yml` as `commit`. The version and that commit are the first line of the debug log and the tooltip of the Source link (`stanpumpRBuild()`; the config first, the DESCRIPTION's `RemoteSha` as a fallback, since shinyapps.io does not carry it), so a live session can be matched to a commit. A manual run (`workflow_dispatch`) deploys the commit it is run on without the check.
- **Windows binary**: every push to `master` rebuilds a Windows binary zip (`.github/workflows/windows-binary.yaml`), installs it into an empty library, runs `.github/scripts/windows-smoke-test.R` under a timeout, and replaces the rolling release `windows-binary` (asset `stanpumpR.zip`, one file for x64 and ARM since the package has no compiled code). It is the documented way to install on Windows (README, `inst/help/scripting.md`, `inst/apidocs/api.md`): a source install there can fail with a bare "lazy loading failed" because Windows 11 Smart App Control blocked a DLL it could not verify during the build.
- **Adding an R package**: add to `DESCRIPTION` first, then `renv::install("pkg")` + `renv::snapshot()`, commit `DESCRIPTION` + `renv.lock` together. For a package that isn't on CRAN, also add it under `Remotes:` in `DESCRIPTION` (e.g. `daattali/undomanager`) and install with `renv::install("user/repo")`, so the deploy can resolve it. A package used only by an optional entry point (plumber for the TCI API) goes in `Suggests`, is guarded with `requireNamespace()`, and is not snapshotted into `renv.lock`.


## The Help Tab (`R/help-*.R`, `inst/help/`)

The in-app help is a `bslib::nav_panel("Help")` with a sidebar (search + contents) and one `uiOutput`. Pages are either Markdown in `inst/help/<id>.md` (rendered by `shiny::markdown()`, i.e. commonmark — no pandoc, no MathJax) or generated from the code: one page per drug (`help-drugs.R` runs the drug model at six reference patients), one per teaching scenario (`help-scenarios.R`), plus the drug index, scenario index and bibliography. `help-content.R` holds the registry (`helpStaticPages()`), the renderer and the search; `help-server.R` is called once from `app_server()`. Links between pages are `[text](help:page-id)`; `[text](scenario:id)` makes a button that calls `applyHelpScenario()`, which writes `doseTable()`/`eventTable()` and the inputs, then `bslib::nav_select()`s the Simulator. All clicks go through three delegated handlers in `inst/www/app.js` (`help_goto`, `help_scenario_load`, `investigator_show`), so the help adds no per-page inputs. `inst/help/README.md` is the authoring guide. Tests: `test-help-content.R`, `test-help-drugs.R`, `test-help-scenarios.R`.

**Investigators** (`R/help-investigators.R`): the bold names on `inst/help/investigators.md` are the registry (`helpInvestigatorRegistry()`: key = surname + first initial, so "Thomas Bouillon" and "Thomas W. Bouillon" are one person and the four Kims are four). `helpLinkInvestigators()` wraps each mention in `<a class="investigator-link" data-investigator="key">` on every help page (`helpPageUI()`), in the citation strings the drug models return (`citationItemHTML()`, so the References panel under the plot too) and in the bibliography; a bare surname links only when it is unique, and `HELP_INVESTIGATORS_CITATION_ONLY` (Shafer) is linked only with `context = "citation"`. The same pass links "GasMan" to its website (`HELP_TERM_LINKS`). The click shows `helpInvestigatorModal()`: every block of the page naming the person, by section, then their `references.md` entries. Adding an investigator is writing the name in bold on that page. Tests: `test-help-investigators.R`.
