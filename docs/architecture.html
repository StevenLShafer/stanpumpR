Architecture Map · R / Shiny package

stanpumpR — a reactive PK/PD anesthetic simulator

A Shiny web app that turns a table of drug doses plus a patient's covariates into predicted plasma and effect-site concentration curves — using closed-form pharmacokinetic solutions rather than a numeric ODE solver. Packaged as a standard R package with a golem-style ui / server / run split.

The request → render pipeline

One reactive chain, dose table to plot

Every edit — a covariate, a dose cell, a graph option — invalidates a link in a single dependency chain inside app_server.R. Shiny re-runs only the downstream reactives. The heavy computation lives in the last two stages.

Resolve pharmacokinetics

server-helpers.RgetDrugPK.R

recalculatePK() walks the drugs named in the dose table and, per drug, calls getDrugPK() to turn the patient's covariates into a full set of rate constants, eigenvalues, and closed-form coefficients. Results are cached on a per-drug list and only recomputed when covariates change.

Simulate concentrations

processdoseTable.RsimCpCe.R

processdoseTable() diffs each drug's doses against the cached result and re-simulates only what changed — calling simCpCe(), which converts dose units, classifies bolus / infusion / oral routes, and dispatches to the right closed-form solver. Output is a tidy time × site table per drug.

WHY IT'S FAST

Both recalculatePK() and processdoseTable() mutate a persistent per-drug list and skip any drug whose inputs are unchanged. Combined with closed-form solutions (no ODE integration), a dose edit re-simulates just the one drug it touched.

The computational core

Closed-form three-compartment kinetics

stanpumpR never numerically integrates. Each drug is a mammillary 3-compartment model with an effect-site link; the disposition is solved analytically once per patient, then evaluated at every time point as a sum of exponentials.

A · Parameterize the patient — getDrugPK.R
drug function → V/Cl
eval(call(drug, weight, height, age, sex)) runs the drug's own covariate model (e.g. Eleveld / Kim for remifentanil) to yield v1..v3, cl1..cl3, tPeak, MEAC.
micro rate constants
Volumes & clearances become k10, k12, k13, k21, k31.
cube() → eigenvalues
cube() solves the characteristic cubic for the disposition rates.
→ lambda_1, lambda_2, lambda_3
effect-site link
tPeakError() + optimize() back-solve ke0 from the drug's time-to-peak-effect.
→ ke0
closed-form coefficients
Per route — bolus, infusion, PO, IM, IN — precompute the exponential coefficients for plasma & effect site.
→ p_coef_* / e_coef_*
B · Advance the doses — simCpCe.R
unit conversion
mg / mcg / ng, per-kg, and per-hour doses are all reduced to base units against the drug's concentration unit.
route classification
Each dose flagged Bolus, infusion, or PO / IM / IN.
solver dispatch
IV, no events → advanceClosedForm0()
oral / IM / IN → advanceClosedFormPO_IM_IN()
time-varying PK events → advanceClosedForm1()
superposition
Each dose's contribution is summed over the exponential basis at every step; convertState.R carries state across PK-event boundaries.
→ Time · Plasma · Effect Site · Recovery
resample & normalize
Curves are interpolated to an even grid (equiSpace), normalized to peak Cp/Ce, and scaled against MEAC.

Drug library — data as code

One function per drug, one CSV for defaults

Adding a drug means adding one drugs_<name>.R file and one row in the defaults CSV — the pattern the project is explicitly built to let outside investigators contribute to.

the model · 23 files

drugs_*.R

Each exports a function drug(weight, height, age, sex) returning compartment PK, tPeak, and MEAC. Bodies encode the published covariate models — often branching on BMI or sex (propofol, remifentanil, dexmedetomidine…). Called by name via eval(call(drug, …)).

state

Saved simulations

URL bookmarking is the default so saved state is a shareable link that works on hosts without server-side storage; opaque server-stored IDs are available where the host supports them (e.g. Posit Connect Cloud). The URL carries no confidential data — bookmarksToExclude drops recipient/comments/exact age and transient UI state, ages 90+ are normalized, and restored state is decoded as JSON and re-validated server-side.
