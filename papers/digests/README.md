# Paper digests (evidence cards)

One markdown file per archived PDF, `<stem>.md` beside `<stem>.pdf`'s name (e.g. `PMID_3100765.md`), so audits of
stanpumpR can read the key facts quickly instead of re-reading the PDFs. A stem ending `_aam`
(`PMID_xxxxx_aam.pdf`, filed by `_build/unpaywall_fetch.py`) is the authors' **accepted manuscript**, the only
open-access version for that work; it is digested like any other PDF but under the rules below, and when the
publisher's PDF later arrives as `PMID_xxxxx.pdf` both files are kept, so the digest built from the manuscript can be
re-checked against the published version. `STATUS.md` (regenerated by
`update.bat` → `_build/digest_prep.py`) lists every archived PDF that still needs a digest; a digest older than its
PDF, or than the last change to the PDF's content (SHA-256 recorded in `_build/pdf_hashes.json`; an OCR rewrite does
not count), is listed as stale.

Inputs for each paper (written by `digest_prep.py`):
- `_build/text/<stem>.txt` — the PDF's text layer (`pdftotext -layout`; form feeds between pages). **A form-feed
  chunk is not always a PDF page**: some PDFs carry literal form feeds inside a page's text, so chunk N can be an
  earlier page (in `PMID_26257511` chunk 16 is PDF page 6). The context file's `pages` is the PDF's own page count;
  where it differs from the chunks, `text_chunks` and `chunk_page` (the PDF page of each chunk, in order) are given,
  and `STATUS.md` lists the file. Cite a PDF page from `chunk_page` or the rendered page, never by counting chunks.
  The text is re-extracted whenever the PDF's SHA-256 changes, but it is still only a copy: check a number that
  matters on the rendered page.
- `_build/context/<stem>.json` — PubMed metadata, the PDF's `sha256`, `pages`, and where stanpumpR cites the
  paper (`locations`, `drugs`, `used_for`, `notes`). `scan: true` means there is no usable text layer: read the page images instead
  (extract the DCT images with pypdf, then view the JPGs; see `_build/memory-reading-scanned-pdfs.md`).

## Rules

- **Facts and paraphrase only.** Numbers, units, table values and design details are facts; copy them exactly.
  Never copy prose: no quoted passage longer than 15 words, at most one per digest.
- **Say where each number comes from**: table/figure/page, and whether it is a typical value, mean, median,
  or a derived value. Mark anything you computed yourself as "(derived: ...)".
- Extract the paper first, *then* compare it with stanpumpR, so the comparison cannot steer the reading.
- **The context file's `locations` say where the repo cites THIS file, not what the repo contains.** Before writing
  that the library has no model for a drug, or does not use a quantity, look at `R/drugs_<drug>.R` and
  `inst/extdata/drugDefaults_global.csv`. (A card once said "there is no ropivacaine model in the library" on the
  strength of a one-line `locations`; `R/drugs_ropivacaine.R` has existed all along.)
- **Where a paper reports pharmacokinetics for a drug the library models, compare them even when the model does not
  cite the paper.** An uncited source is an independent check, and that pairing is often a card's most useful
  output: the Naropin label against the Simon 2006 ropivacaine set, Baumann 1976 against Fabian 1969. Say which
  direction any difference runs and whether the model's own header already predicts it.
- Record what the paper does not report (e.g. "no ke0 reported", "weight not given") rather than guessing.
- **A comparative word is a claim with a hidden second half.** When a source says a parameter is higher, lower,
  shorter or faster, name what it was measured AGAINST; and if stanpumpR applies that claim against a different
  baseline, say so, or ask a `[source]` question. Kokki 2012's "clearance was higher" in labour meant higher than
  another study's volunteers, not higher than the library's own non-pregnant model, against which those women are
  in fact 0.89x. The unexamined word carried a 64% error into the plotted curve of every pregnant patient given
  oxycodone, for as long as it went unchecked (`digests/PMID_30652261.md`).
- **Machine-readable** (checked by `digest_prep.py`, listed under "Card format problems" in `STATUS.md`): the
  frontmatter and every fenced `yaml` block must parse with PyYAML. Wrap `citation` and `source_read` in double quotes
  (titles carry ": "); quote any flow-mapping value containing a comma, colon, quote, bracket or `*`. Every card has a
  `yaml` block starting `parameters:` (`parameters: []` with a comment when there are none). `verification:` is
  exactly one of the four values, with nothing after it; put the detail in the body. A correction made later adds
  `revised: YYYY-MM-DD (what changed)` after `verification:`.
- **Page references**: give the PDF page (one-based in the archived file) and the printed page where they differ.
- **Never guess an ambiguity the paper and the code cannot settle.** Record it as an entry in the frontmatter list
  `open_questions:`, one line each, saying what is unresolved and what would settle it. **Start each with its
  kind**: `[decision]` when only Steven L. Shafer can settle it (a dose basis the source leaves open, a value to
  keep or change), `[source]` when another paper, a supplement or the full text would, `[check]` when re-reading a
  rendered page would. `digest_prep.py` collects them into `digests/REVIEW.md`, grouped by kind. A question is closed by REVISING the card: drop it from `open_questions`, write the
  answer under *Verification against stanpumpR*, and add a `revised:` line. Omit the key when there are none.
- **`reviewed: YYYY-MM-DD (who)`** is added when a person has read the card against its PDF and is content with
  it. It is never written by the session that wrote the card, and an unattended run never writes it.
- **An accepted manuscript (`_aam`) cites PDF pages only.** It has no printed pagination, and its tables can move or
  change at proof, so never give a printed page or journal page range for a number read from one, and say in
  `source_read` that the file is the accepted manuscript. Where such a digest records a number an implemented
  stanpumpR model pins, say so in *Verification against stanpumpR*: that line is what a later reader re-walks against
  the published PDF. Digest a manuscript rather than waiting for the publisher's file -- an unread source a model
  depends on is the larger risk -- but a work no implemented model depends on can wait.

## Template

````markdown
---
file: PMID_xxxxx.pdf
pmid: xxxxx
doi: ...
citation: "Author A, Author B, et al. Title: subtitle. Journal Year;Vol:pages."
kind: pk-model | pkpd-model | pd-study | meac/analgesia | clinical-trial | review | label | methods | other
drugs: [drug, ...]          # stanpumpR drug names the paper is about
source_read: "text layer | page images | partial (say which pages)"
edition: published | accepted_manuscript   # omit for published; required on an `_aam` file
digest_by: Claude Opus 5.5, YYYY-MM-DD     # or: Claude (unattended digest_run.py), YYYY-MM-DD
checked_against: stanpumpR master <short sha>
verification: matches | discrepancy | partly-verified | not-applicable
open_questions:                            # omit when there are none
  - what is unresolved, and what would settle it
reviewed: YYYY-MM-DD (who)                 # added by a person, never by the card's own session
---

# First-author Year: short title

## Study
Design, population (n, age, weight, sex, health), drug/route/dose, sampling, assay, model and software.

## Model and parameters
Structural model and parameter table with units (and SE/%CV/IIV where given), with the table/page cited.
A YAML block for machine reading:
```yaml
parameters:
  - {name: V1, value: 2.19, unit: L, source: "Table 3", note: typical value}
```

## Pharmacodynamics and end points
ke0 / t½ke0 / tPeak, EC50, Emax, gamma, MEAC or analgesic concentration, the **end point** each was measured on
(EEG, pupil, CSF, pain score, PCA demand...), and any potency ratio stated.

## Covariates
Which, and their equations.

## Caveats
Limitations the authors give, and any you notice (small n, healthy volunteers, assay limits, a fitted value
at a bound...).

## Used by stanpumpR
From the context file: each repo location and what it uses the paper for.

## Verification against stanpumpR
For each location: what the code/help/test says, what the paper says, and a verdict
(**matches** / **discrepancy** / **cannot verify**). Check unit conversions, per-kg vs absolute values,
minutes vs hours, ke0 vs t½ke0 vs tPeak, and transcription. Discrepancies are reported, never fixed here.
````
